## API (as implemented)

**dk-curve.** FIELDS `pos name grains of`. Fields: `src` (`d0-fit.json`), `sets` (path or
list of paths; a set is an array in `model.params` order, `{ p, chi2 }`, or an object whose
`'@path'` strings are read from the same file), `f` (`gauss+poly1 | gauss+exp | exp | poly1
| flat | decay`), `pivot`, `bin`, `names`, `range`, `pull` (`false` or `{ data, counts, err,
eval: centre|integral, y, height, max }`), `readout` (`chi2` = Σ pull² of the curve as drawn,
or a parameter name), `flow`, `thick`, `dash`, `ease`, `draw`, `alpha`, `seed`, `steps`.
Step keys: `set`, `parts`, `pull` (merged as dk-hist's; without `steps`, step k = set k−1).
Step 0 hidden. From hidden, an arrival or `c`: waits for the hist's `busy` to clear (at
most 12 s), then draws on from the left in 1.2 s. Forward: parameters glide 1.4 s; back:
0.35 s. api: `arm assemble busy value values() params() sets() pulls() ready()`. Events:
none; everything is a world-clock transition from the step state (no event uniforms, so no
eventLatch). The line flow is idle motion on t and never busy.

**dk-landscape.** FIELDS `pos name grains`. Fields: `src` (`d0-chi2.json`), `key`, `dims`
(1|2), `under`, `at`, `size`, `height`, `zmax`, `below`, `flip`, `mesh`, `lines`, `alpha`,
`levels` ([1]), `ball {grains, r}`, `roll {legs, leg}`, `slice {zmax 4, zoom, height,
lift, dim, decimals, grains}`, `ticks`, `tickPx`, `word`, `readout` (`x | y | d | chi2`),
`seed`, `steps`. Step keys: `surface`, `roll`, `ring`, `slice`. Default steps dims 2:
`[0, {}, {roll}, {ring}, {slice}]`; dims 1: `[0, {}, {roll}, {ring}]`. The surface is a
kit morph (gathers from a loose cloud, rim first); ring, slice, extras, trail and ball are
`dotGrains`. api: `arm assemble busy value values() ready()`. No event uniforms.

Both: seeded (mulberry32 from `seed`, default 401), colours from `roles(ctx.palette)` only,
`frameScale` returned at build, every count within `ctx.budget`, `grains` declared,
everything created is disposed (`dispose()` also removes the grains it put into the hist's
groups and unregisters the name).

## Decisions

1. **CPU-placed curve grains.** The curve's grains (a few thousand) are placed each frame on
   the CPU from an arc-length table of the model, so the steep flanks are as dense as the
   flat background and the grains drift along the line on t. Alternative: a shader with
   the parameters as uniforms (x-uniform spacing, thin flanks).
2. **The curve lives in the hist's plot group** and reads its y scale from `frame().y(1)`
   (eased when the hist rescales), so it tilts with `{tilt}` and fits any hist bin width.
3. **χ² on screen is computed, not interpolated:** the readout is Σ pull² of the curve as
   drawn over the bake's bin data, so the count runs through real values while the curve
   glides.
4. **The bowl hangs under the floor in front of the plot** (rim at the floor, its minimum
   under the peak's x), so the tilted plot and the valley do not overlap on screen.
   Alternative: under the tilted plot's area (they overlap additively; busy).
   Review fix: the plot is hidden while the bowl stands (two μ scales one above the other
   read as one), and the bowl is cropped with `range`.
5. **The rising slice (dims 2 `{slice}`) is opt-in now**, no longer in the default steps: the
   review found plot, bowl and slice in one frame too busy. The error gets its own dims-1
   slide. When used, the bowl's ticks fade out while the slice stands.
   **It stays within the bowl's own height** (from its bottom to its rim, in
   the minimum's plane, magnified), because rising above the rim crossed the plot.
6. **Linear height** in Δχ² (a true paraboloid); `zmax` defaults to just above the path's
   start so the start is on the surface (about 290 for d0-chi2.json).
7. **Rings from the grid** by marching squares (any level, loss grids too); the slice and
   its crossings are the bake's when the file has them.
8. **The lab's headmatter is `layout: default`** (cover put the `.nums` at the top).
