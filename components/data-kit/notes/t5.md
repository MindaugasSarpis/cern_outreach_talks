## API

`{ type: 'dk-pipeline', name, pos, grains, stages: [...], run: { seconds 8, lead 0.4,
twice true, third false }, flow 2500, sweeps 3, alpha 1.1, flowAlpha 0.9, sweepAlpha 0.75,
seed 401 }`. FIELDS = `pos name stages grains`. Stage kinds:

- `pile` { at, r 2.1, n 91583, spin 0.06, alpha 0.32, ours 0 }. The file as a ball of n
  grains, one a candidate, as many as `ctx.budget` allows after the pipeline's own grains
  (91 583 at tier 0). It turns slowly, and our row is at size 2.5 on the side the camera sees.
- `code` { at, size [w,h], src 'code-lines.json', script, lines [a,b], cols 1, gap 0.5,
  typing 2.2 }. One grain row per real line; every non-blank run of characters is a run of
  grains, one grain a character. Indent, length and the gaps between words are the file's own.
- `sheet` { at, size, values 'd0.f32', rows 90, pages 1, cell 14, stride 1, columns }. The
  CSV as rows × 4 columns of value grains. Each value is a dash of 14 grains with brightness
  0.3 + 0.7 × its rank in its column, ranked over all 91 583 rows. A missing TAU leaves its
  cell dark. The rows drawn are file rows 1-90.
- `hist` { of }. It draws nothing of its own. The deck's dk-hist fills out of the last
  code stage (`from` / `fromSpread` = `api.outlet()`, `fill` 7.5).

Steps: 0 hidden · 1..S the stages one at a time (code is typed in; a sheet is written as the
stream reaches it, and its run goes from the file to the sheet; a hist stage runs the
whole chain) · S+1 run 2 · S+2 third (only with `run.third`). Step back: 0.35 s, no run.
Arrival or `c`: replays from nothing, with earlier stages appearing quickly and the newest
building.

Clock and events: every grain is either a morph state (kit morph.js, two morphs: the
turning ball and the flat stages) or a stream or sweep grain whose place follows from
`uRun0` and world `t` alone. `uRun0` / `uRunEnd` sit in a `stage.eventLatch` that is
stopped when the run has passed, so the times go back to OFF and nothing carries into
another slide. A new run resets them first. There is no `performance.now` and no
`setTimeout`. All randomness is seeded mulberry32. Colours come from roles: crowd for
the ball, code, sheet and streams; sel for the sweeps and the read/write head; nothing
dim, nothing gold.

`api`: `value()` (sheet rows written, scaled to 91 583: `<StageCount for="pipe">`), `busy`
(loading, armed, gathering, typing, writing, a run in flight), `outlet(k)`, `box(k)`,
`scripts()`, `ready()`, `step()`. `dispose()` frees both morphs and both stream materials
and unregisters the name.

## Open

- **Rows shown:** the sheet draws the first 90 of 91 583 rows; the count is in .nums.
  The alternative is `stride: 1018`, every 1 018th row across the whole file. Notes must
  say which one is shown.
- **Run 1 white:** the bible and the task make run 2 light blue, so run 1 is `tone: 'sel'`
  (white). That uses "white = selected" for "the original". The alternative is run 1
  light blue and run 2 white.
- **Code shown:** root_to_csv.py (whole) and d0.py 87-208 (`read` … `lm`: the read, bin and
  fit). Both use the same line pitch (0.15 and 0.148), so their lengths compare truly.
  d0.py is the bake's script; Talk 5's notes should name both, with their sha256 from
  code-lines.json.
- **Third run:** supported as a step, but it needs a third dk-hist (91 583 more grains,
  which puts the slide past 500k). With no D⁰ version case computed, I recommend reusing run 2:
  step h2 to 0 and back to 1 on the third-run click. This is not tried.

  lines could stand for it; that is the owner's call.
- **Peak row:** the bible (T5 'Choices before looking') asks for a row of peak ticks under the
  refilling histogram. After review the lab shows the peaks as their own histogram on their own
  pose instead; the owner should confirm this change to the bible's picture.
